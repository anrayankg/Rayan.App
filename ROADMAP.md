## Текущий этап
**Этап 4 — Карточка объекта и логика статусов. Основная часть готова, доделываем детали.**

См. также `TESTING_GUIDE.md` в корне репозитория — там подробно, как проверить каждую готовую вещь.

Этапы 1-3 по факту сделаны в ходе редизайна главной страницы (см. app/page.jsx, app/globals.css):
тёмная/светлая тема по системным настройкам телефона, сетка карточек 2×N, человеческие названия категорий,
формат характеристик, адрес через район/ЖК, поиск и вкладки Активные/Новые, картинки категорий (Квартиры,
Новостройки, Дома, Участки, Коммерческая, Аренда — готовы; Иссык-Куль и Инвестиции ждут картинок от Айгуль).
Этап 2 (пошаговый мастер) по-прежнему реализован как раскрывающиеся секции на одной странице, а не отдельный
экран на шаг — сверено с Айгуль устно, менять не просили, оставлено как есть.

**Готово по трём видам страницы объекта** (подробности и ссылки — в TESTING_GUIDE.md):
- Клиент — `app/p/[id]/page.jsx`
- Агент (чужой объект) — `app/a/[id]/page.jsx`
- Договорник (свой объект) — по-прежнему старая внутренняя страница `app/listing/[id]/page.jsx`, работает,
  но НЕ переоформлена в новый визуальный стиль (как /p/ и /a/) — отдельная задача, не начата.

**Личный кабинет агента** (`app/profile/page.jsx`) — упрощённый вход по рабочему номеру телефона,
БЕЗ пароля (сознательное решение Айгуль на первое время). Таблица `agents` в Supabase, RLS отключён на
agents и collections (иначе приложение не может ни читать, ни писать). Первый живой агент — Насреддин.

**Видеообзор объекта** — готов целиком, все три вида страницы.

**Подборки** (`app/c/[id]/page.jsx`, `components/AddToCollectionButton.jsx`) — готовы: создание, добавление
объектов, отправка через WhatsApp/Telegram/MAX. **Не реализовано:** персональная замена цены/описания и
номера агента конкретно в рамках подборки при отправке клиенту — обсуждали, не построили. Следующая задача.

**Счётчик "Новые"** на главной — считает по published_at ИЛИ created_at, смотря что раньше сработает.

## Полный план этапов
1. Редизайн приложения (тёмная тема, сетка карточек 2×N)
2. Пошаговая форма добавления объектов (мастер по шагам вместо одной длинной формы)
3. Поиск и фильтры
4. Карточка объекта и логика статусов
5. Центр рекламы (раздел "Реклама", кнопка "Запустить рекламу")
6. Интеграция Lalafo — **после** исследования официального API
7. Интеграция House.kg — после исследования API
8. Instagram / Facebook — после исследования Meta API
9. TikTok / Threads — после исследования API
10. Telegram / WhatsApp Business — после исследования официальных API
11. Единый центр сообщений (все площадки в одном разделе "Чаты")
12. Автоматическая очередь рекламных задач агента ("Сегодня нужно прорекламировать: N")
13. Статистика и аналитика рекламы

## Важные принципы (не менять без согласования)
- Для каждой интеграции (6-10): сначала проверить, есть ли официальный API и что именно он разрешает. Никаких неофициальных обходов блокировок.
- Если официального API нет — делать удобный ручной сценарий (открыть площадку → нужный объект → подготовленный текст/фото → агент делает сам вручную), а не обещать автоматизацию.
- Главное при публикации — не плодить дубли объявлений, если существующее можно обновить/поднять.
- При конфликте между roadmap и текущим кодом — сообщить Айгуль, не менять бизнес-логику самостоятельно.
